# ЛР2 — «Кібер-Дієта»

Матеріал роботи: **https://docs.sp.ordynski.com/labs/lab02/story.html**
Формальний опис, порядок виконання й контрольні питання: там само, вкладка «академічна».

Цей репозиторій — **рівень 1** (оцінка «3»). Рівні 2 і 3 виконуються у власному
наскрізному репозиторії `vtfk-sid` і здаються на захисті.

---

## Як почати

1. Натисни **Code → Codespaces → Create codespace on main**.
2. Зачекай, поки середовище збереться (перший раз — кілька хвилин).
3. Перевір, що Docker на місці:

   ```bash
   docker version
   ```

   Мають вивестися блоки `Client:` і `Server:` без помилок з'єднання з демоном.

Коли здаси роботу — **видали простір**: `https://github.com/codespaces` → `…` → **Delete**.
Сховище витрачає твою квоту, доки простір існує, навіть зупинений, а образи Docker із цієї
роботи важать гігабайтами.

---

## Що треба здати

У корені цього репозиторію:

```
src/main.rs         простий бінарник: друкує рядок і виходить із кодом 0
Cargo.toml          маніфест пакета
Cargo.lock          зафіксовані версії залежностей
Dockerfile.naive    наївна ОДНОЕТАПНА збірка — мірило «до оптимізації»
Dockerfile          підсумкова БАГАТОЕТАПНА збірка
.dockerignore       щоб `target/` і `.git/` не їхали в контекст збірки
REPORT.md           розміри до й після, вивід `docker history`, висновок
```

Готового коду в шаблоні немає навмисно — це і є робота.

### Контракт `Dockerfile.naive`

Один етап `FROM` повнофункціональної ОС або повного тулчейну (наприклад `rust:1.79`),
у якому встановлюється все потрібне, компілюється бінарник і одразу запускається. Це
**контрольний замір**, а не зразок для наслідування: він має бути великим.

### Контракт `Dockerfile`

- Щонайменше **два етапи** `FROM`: етап збірки й фінальний етап запуску.
- Фінальний етап бере з етапу збірки **лише готовий бінарник**, через
  `COPY --from=<ім'я-етапу>`. Двох `FROM` без цього рядка недостатньо: тоді етапи не
  зв'язані, і образ лишається таким самим важким.
- Фінальний етап — мінімальний дистрибутив (`debian:12-slim` або `alpine`).
- `ENTRYPOINT` або `CMD` запускає скопійований бінарник напряму.

Порядок інструкцій у етапі збірки — спершу копіювання `Cargo.toml` і `Cargo.lock` та
компіляція залежностей окремим шаром, потім решта коду. На рівні 1 це не перевіряється
автоматично, але саме про це йтиметься на захисті рівня 2.

## Як здати

Здача — **тег**, не просто пуш. Пуші безкоштовні й нічого не запускають; перевірка
стартує на тезі `submit/*`:

```bash
git tag submit/lab02
git push --tags
```

Результат з'явиться у вкладці **Actions** цього репозиторію й у релізі за тегом.

**Повторна здача — переставленням того самого тега**, а не новим:

```bash
git tag -f submit/lab02
git push -f --tags
```

Кількість спроб не обмежена, доки відкритий модуль. Тег на лабораторну **один** —
`submit/lab02`.

## Що перевіряється

| # | Перевірка |
|---|---|
| 1 | `Dockerfile`, `Dockerfile.naive` і `src/` на місці |
| 2 | `Dockerfile` багатоетапний і етапи зв'язані через `COPY --from` |
| 3 | `Dockerfile` збирається |
| 4 | `Dockerfile.naive` збирається (потрібен як мірило розміру) |
| 5 | фінальний образ **менший за 50 %** наївного |
| 6 | образ запускається, друкує рядок і завершується кодом `0` |

Рівень 1 зараховується, **коли пройшли всі шість**.

Перевірка збирає обидва образи сама й міряє їх сама — числа з `REPORT.md` вона не читає.
Тому образ, про який «написано, що він менший», не пройде: меншим він має бути насправді.

## Підказки

- Статичний бінарник без зовнішніх бібліотек: `--target x86_64-unknown-linux-musl` для Rust
  або `CGO_ENABLED=0` для Go. Без цього фінальний образ вимагатиме тих самих бібліотек, що й
  етап збірки, і схуднути не вийде.
- Іменуй етап: `FROM rust:1.79 AS build`, далі `COPY --from=build …`. Номер (`--from=0`) теж
  працює, але з іменем помилитися важче.
- Порівняти розміри: `docker images | grep lab02`. Ці числа й ідуть у `REPORT.md`.
- `docker history <образ>` показує, який шар дав найбільший приріст, — саме це й треба
  пояснити у звіті.
- Роздувати `Dockerfile.naive`, щоб відношення зійшлося, немає сенсу: баласт лишиться
  рядком у файлі, який читають на захисті.
